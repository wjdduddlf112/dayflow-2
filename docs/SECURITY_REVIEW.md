# 보안 검토

검토일 2026-10-30 KST. 최초 업로드 전 모든 도달 가능한 Git blob 47개를 검사하고 원격 origin이 사용자 승인한 github.com/wjdduddlf112/dayflow-2인지 확인했다. 실제 API 키·개인키·인증 비밀값·DB 파일은 패턴 검사상 발견되지 않았다. 후속 커밋도 `npm run audit:history`로 재검사한다. 검사는 의심값을 출력하지 않고 경로/규칙만 보고한다.

고정 문자열 비밀번호/주소/일정은 테스트 fixture와 문서 예시이며 운영 비밀값/개인 일정이 아니다. 키 생성 테스트는 임시 키를 파일로 만든 후 제거했고 로그에 값을 쓰지 않았다. .dev.vars, .env, DB 상태, dist, node_modules, 테스트 생성물은 Git에서 제외된다. Git 이력의 통상적인 작성자 이름/이메일 메타데이터는 승인된 이력과 함께 보존한다.

수정한 주요 항목:

- Zod 4.6.7과 Vitest 5.0.5로 보고된 Zod/mocker/Tinypool 취약점 해결. npm audit 전체 0건 확인. 취약점 데이터는 시점에 따라 달라진다.
- 입력을 UTF-8 바이트 기준 20KB에서 중단하고 JSON 오류는 400, 과대 입력은 413. 잘못된 실제 날짜와 종료시간/반복 요일을 서버에서 검증한다.
- Gemini HTTP 오류/timeout/스키마 실패는 안전한 메시지로 변환하며 원래 응답 본문/키/메모를 노출하지 않는다. 키는 서버 헤더에만 포함한다. Interactions는 store=false로 요청하고 관련 후보의 설명은 전송하지 않는다.
- AI 수정은 changedFields와 DB snapshot/버전 검증을 거쳐 기존 값에 병합한다. 삭제·변경·완료는 사용자 확인과 기존 대상 ID가 필요하다.
- 반복 완료와 원본 버전 갱신을 D1 batch/guard 제약으로 묶어 동시 요청의 한 건만 성공하도록 한다.
- 개인 API는 세션 인증, 모든 변경은 동일 Origin 검사. HttpOnly/Secure/SameSite=Strict 쿠키, PBKDF2, 로그인 시도 제한과 로그아웃을 workerd에서 검사했다.
- 알림 꺼짐과 별개로 만료 인증 상태를 정리한다. 푸시 구독 URL은 허용된 Push 서비스 호스트만 받아 SSRF 범위를 제한한다.
- 프로덕션 정적 자산에 strict script-src CSP/nosniff/no-referrer를 적용한다. 개발용 React preamble의 인라인 허용은 로컬 개발 응답에 한정한다. API는 no-store이며 Service Worker는 캐시하지 않는다.
- 키 생성 스크립트는 실제 부모 경로를 해석해 저장소 내부/심볼릭 링크 경로로의 오저장을 차단하고 권한 0600 / 배타적 생성을 사용한다.

검사 한계: 자동 패턴 검사만으로 모든 민감 데이터 형식을 검출할 수 없다. 실제 클라우드 계정의 키 권한, 무료 플랜/청구 상태, 원격 방화벽 및 실기기 보안은 확인하지 않았다. 배포 승인과 실제 설정 후 운영 검증이 필요하다.
